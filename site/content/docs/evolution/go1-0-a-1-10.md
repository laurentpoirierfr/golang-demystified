**Mars 2012 à février 2018.** Les six premières années de Go 1 ont posé les
fondations : un langage stable, un runtime de plus en plus performant et un
outillage qui s'enrichit à chaque version.

## Go 1.0 — mars 2012

Après deux ans et demi de développement public, Go 1.0 fige le langage et la
bibliothèque standard. La [promesse de compatibilité](https://go.dev/doc/go1compat)
garantit que les programmes écrits pour Go 1 continueront de compiler et de
fonctionner avec les versions suivantes. Elle a été tenue depuis.

Go 1.0 apporte déjà l'essentiel : goroutines et channels, interfaces
implicites, `go fmt`, `go test`, `go doc`, compilation croisée, et une
bibliothèque standard qui comprend `net/http`, `encoding/json` et
`crypto/tls`.

## Go 1.1 — mai 2013

- Le **détecteur de courses** (`-race`) fait son apparition.
- `int` et `uint` passent à 64 bits sur les plateformes 64 bits.
- Les **valeurs de méthode** : `f := obj.Methode` donne une fonction liée à
  `obj`.
- Des gains de performance de 30 à 40 % grâce à un meilleur compilateur et un
  meilleur GC.

## Go 1.2 — décembre 2013

- Les **expressions de slice à trois indices** `s[a:b:c]` limitent la capacité.
- La **couverture de code** : `go test -cover`.
- Le nombre maximal de threads devient réglable, et les goroutines sont
  préemptées à l'entrée des fonctions.

## Go 1.3 — juin 2014

- Les piles de goroutines deviennent **contiguës** : elles sont recopiées
  lorsqu'elles grandissent, ce qui supprime le problème des « piles
  segmentées ».
- `sync.Pool` permet de réutiliser des objets temporaires.

## Go 1.4 — décembre 2014

- `for range x { … }` sans variable.
- Les **packages `internal`** ne sont importables que par leur arborescence
  parente.
- `go generate` lance les générateurs de code déclarés par des commentaires
  `//go:generate`.
- Le runtime est en grande partie réécrit de C en Go, et Android devient une
  cible officielle.

## Go 1.5 — août 2015

Une version charnière :

- Le compilateur et le runtime sont désormais **écrits en Go** : il n'y a plus
  de code C dans la chaîne de compilation.
- Le **ramasse-miettes devient concurrent**, avec des pauses visées sous les
  10 ms.
- `GOMAXPROCS` vaut par défaut le nombre de cœurs (au lieu de 1).
- L'expérience `vendor/` permet d'embarquer les dépendances dans le projet.

## Go 1.6 — février 2016

- **HTTP/2** est activé automatiquement pour les clients et serveurs HTTPS.
- Le répertoire `vendor/` est activé par défaut.
- Le runtime détecte certains accès concurrents aux maps et arrête le
  programme.

## Go 1.7 — août 2016

- Le package **`context`** rejoint la bibliothèque standard, et `net/http`
  l'intègre aux requêtes.
- Les **sous-tests** et sous-benchmarks avec `t.Run`.
- Un nouveau backend de compilation basé sur la forme **SSA** produit un code
  5 à 35 % plus rapide sur amd64, et des binaires plus petits.

## Go 1.8 — février 2017

- Les pauses du GC passent **sous les 100 microsecondes**.
- `sort.Slice` trie une slice avec une simple fonction de comparaison.
- `http.Server.Shutdown` arrête un serveur proprement.
- Les **plugins** (`-buildmode=plugin`) sur Linux.
- `GOPATH` prend une valeur par défaut : `$HOME/go`.

## Go 1.9 — août 2017

- Les **alias de types** (`type A = B`) facilitent le déplacement de types
  entre packages lors des refactorisations.
- `sync.Map`, une map concurrente optimisée pour certains usages.
- `math/bits`, des opérations sur les bits accélérées par le processeur.
- `time.Now()` inclut une **horloge monotone** : les mesures de durée
  deviennent fiables.

## Go 1.10 — février 2018

- Le **cache de compilation** : `go build` ne recompile que ce qui a changé.
- Le **cache des tests** : `go test` ne réexécute pas un test dont ni le code ni
  les entrées n'ont changé.
- `go test` exécute automatiquement une partie de `go vet`.
- `strings.Builder` construit des chaînes efficacement.

## À retenir

En 2018, Go est un langage mûr et performant, mais il lui manque deux choses
que la communauté réclame depuis le début : une **gestion des dépendances**
officielle et les **génériques**. Les versions suivantes vont s'y atteler.
