# Chapitre IV.2 — Go 1.11

**Août 2018.** La fin du `GOPATH` commence : Go 1.11 introduit les **modules**.

## Les modules

Jusque-là, tout le code devait vivre dans `$GOPATH/src`, sans notion de
version : `go get` récupérait la dernière version de chaque dépendance. La
communauté avait multiplié les outils pour combler ce manque (godep, glide,
dep…).

Go 1.11 ajoute un support **expérimental** des modules :

- un fichier `go.mod` déclare le chemin du module et ses dépendances
  versionnées ;
- `go.sum` enregistre les empreintes cryptographiques des dépendances ;
- un projet peut se trouver n'importe où sur le disque ;
- la sélection de version minimale (*Minimal Version Selection*) garantit des
  builds reproductibles sans fichier de verrouillage.

Les modules sont activés hors du `GOPATH`, ou partout avec la variable
`GO111MODULE=on`. Cette variable, qui doit son nom à cette version, a
longtemps accompagné les développeurs Go.

## WebAssembly

Un nouveau port expérimental, `GOOS=js GOARCH=wasm`, compile un programme Go
en WebAssembly pour l'exécuter dans un navigateur. Le package `syscall/js`
permet d'interagir avec JavaScript.

## Autres nouveautés

- `runtime/trace` permet d'annoter les traces d'exécution avec des tâches et
  des régions définies par l'utilisateur.
- Les informations de débogage des binaires optimisés sont nettement
  améliorées.

## À retenir

Go 1.11 ouvre la transition vers les modules, qui va durer jusqu'à Go 1.16.
Voir le chapitre [L'outil go](../../decouvrir/outil-go/) pour leur
utilisation actuelle.
