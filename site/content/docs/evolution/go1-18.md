# Chapitre IV.9 — Go 1.18

**Mars 2022.** La plus grande évolution du langage depuis Go 1.0 : les
**génériques**.

## Les génériques

Après plus de dix ans de débats et plusieurs propositions abandonnées, les
paramètres de type arrivent dans le langage :

```go
func Map[T, U any](s []T, f func(T) U) []U {
	out := make([]U, 0, len(s))
	for _, v := range s {
		out = append(out, f(v))
	}
	return out
}

type Pile[T any] struct{ elements []T }
```

Avec eux arrivent :

- `any`, alias de `interface{}` ;
- `comparable`, la contrainte des types comparables avec `==` ;
- les **ensembles de types** dans les interfaces (`~int | ~float64`) ;
- l'inférence des arguments de type.

Les packages `slices` et `maps` sont d'abord publiés dans
`golang.org/x/exp`, le temps de stabiliser leur API.

## Le fuzzing

Le fuzzing est intégré à `go test` : une fonction `FuzzXxx` reçoit des
entrées générées automatiquement, et les cas qui provoquent un échec sont
conservés dans `testdata/fuzz`.

## Les workspaces

Un fichier `go.work` permet de travailler sur plusieurs modules à la fois,
sans directives `replace` temporaires :

```bash
go work init ./service ./bibliotheque
```

## Autres nouveautés

- `strings.Cut` et `bytes.Cut` découpent autour d'un séparateur.
- `net/netip` fournit un type d'adresse IP compact, immuable et comparable.
- Les exécutables enregistrent les informations du gestionnaire de versions
  (commit, date, état modifié), lisibles avec `go version -m`.
- `GOAMD64` permet de cibler des processeurs récents (`v2`, `v3`, `v4`).
- Les appels par registres sont étendus à arm64 et ppc64.

## À retenir

Les génériques ont transformé la bibliothèque standard des versions
suivantes : `slices`, `maps`, `cmp`, `iter`, `sync.OnceValue`… Voir le chapitre
[Génériques](../../langage/generiques/).
