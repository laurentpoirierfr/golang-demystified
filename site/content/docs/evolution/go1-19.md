**Août 2022.** Une limite de mémoire souple, des types atomiques, et un modèle
mémoire clarifié.

## Runtime : GOMEMLIMIT

Le ramasse-miettes accepte une **limite de mémoire souple**, avec la variable
`GOMEMLIMIT` ou `debug.SetMemoryLimit`. À l'approche de la limite, le GC
travaille davantage pour la respecter. Dans un conteneur à mémoire limitée,
c'est le moyen d'éviter un arrêt pour manque de mémoire sans désactiver le GC.

```bash
GOMEMLIMIT=900MiB ./service   # pour un conteneur limité à 1 Gio
```

## Modèle mémoire et types atomiques

Le **modèle mémoire** de Go, qui définit ce qu'une goroutine peut observer des
écritures d'une autre, est révisé et aligné sur ceux de C, C++, Java et Rust.

Le package `sync/atomic` gagne des **types** qui évitent les erreurs
d'alignement et les accès non atomiques par mégarde :

```go
var compteur atomic.Int64
compteur.Add(1)

var config atomic.Pointer[Config]
config.Store(nouvelle)
```

## Commentaires de documentation

Les commentaires de documentation acceptent des **liens** (`[strings.Cut]`,
`[texte]: URL`), des **listes** et des **titres** (`# Titre`). `gofmt`
reformate ces commentaires.

## Sécurité : os/exec

`exec.Command` et `exec.LookPath` ne trouvent plus un exécutable situé dans le
répertoire courant via `PATH`. Cette correction ferme une faille classique,
notamment sous Windows.

## Autres nouveautés

- `fmt.Append`, `fmt.Appendf` et `fmt.Appendln` écrivent dans une slice
  d'octets.
- Les `switch` sur des entiers ou des chaînes nombreuses sont compilés en
  tables de saut, jusqu'à 20 % plus rapides.

## À retenir

En production, fixez `GOMEMLIMIT` un peu en dessous de la limite mémoire du
conteneur.
