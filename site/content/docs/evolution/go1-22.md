**Février 2024.** La correction d'un piège historique, et un routeur HTTP
complet dans la bibliothèque standard.

## Une variable par itération

Avant Go 1.22, la variable d'une boucle `for` était **partagée** par toutes
les itérations. Les closures et les goroutines qui la capturaient voyaient
toutes la dernière valeur :

```go
for _, v := range valeurs {
	go func() {
		traiter(v) // avant Go 1.22 : souvent la dernière valeur !
	}()
}
```

Ce piège était l'une des erreurs les plus fréquentes en Go. Depuis Go 1.22,
**chaque itération a sa propre variable**. Le changement ne s'applique qu'aux
modules qui déclarent `go 1.22` ou plus, pour ne casser aucun programme
existant. Les copies `v := v` deviennent inutiles, et `go fix` les supprime.

## range sur un entier

```go
for i := range 10 {
	fmt.Println(i) // de 0 à 9
}
```

## Le routage HTTP

`http.ServeMux` accepte les méthodes et les paramètres de chemin :

```go
mux.HandleFunc("GET /articles/{id}", detail)
mux.HandleFunc("POST /articles", cree)

id := r.PathValue("id")
```

Pour la plupart des API, les routeurs externes ne sont plus nécessaires.

## Bibliothèque standard

- **`math/rand/v2`** : la première « v2 » de la bibliothèque standard, avec de
  meilleurs algorithmes et une API générique (`rand.N`).
- `cmp.Or` renvoie la première valeur non nulle.
- `slices.Concat` concatène plusieurs slices.
- `database/sql.Null[T]` représente une colonne qui peut être `NULL`, quel que
  soit son type.
- `go/version` compare des versions de Go.
- `http.FileServerFS` sert un `fs.FS`.

## Aperçu : les itérateurs

L'expérience `GOEXPERIMENT=rangefunc` permet de tester `range` sur des
fonctions, qui arrivera en Go 1.23.

## À retenir

Si votre `go.mod` déclare une version antérieure à 1.22, passer à une version
plus récente corrige silencieusement toute une classe de bugs. Voir les
chapitres [Contrôle de flux](../../langage/controle/) et
[HTTP](../../bibliotheque/http/).
