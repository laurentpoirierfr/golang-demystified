**Septembre 2019.** L'enveloppement des erreurs et l'infrastructure publique
des modules.

## Enveloppement des erreurs

Go 1.13 standardise une pratique que les bibliothèques réinventaient chacune
à sa manière : ajouter du contexte à une erreur sans perdre l'erreur
d'origine.

```go
if err != nil {
	return fmt.Errorf("lecture de %s : %w", chemin, err)
}

if errors.Is(err, fs.ErrNotExist) { … }

var pe *fs.PathError
if errors.As(err, &pe) { … }
```

- le verbe `%w` de `fmt.Errorf` enveloppe une erreur ;
- `errors.Is`, `errors.As` et `errors.Unwrap` parcourent la chaîne
  d'erreurs.

## Les littéraux numériques

Les littéraux deviennent plus lisibles et plus complets :

```go
masque := 0b1010_1010     // binaire
droits := 0o755           // octal explicite
million := 1_000_000      // séparateur
flottant := 0x1p-2        // hexadécimal flottant : 0.25
```

Les décalages acceptent aussi des quantités signées : `x << n` avec `n int`,
sans conversion en `uint`.

## Le proxy et la base de sommes de contrôle

Les modules sont désormais téléchargés via **`proxy.golang.org`** par défaut,
et leur contenu est vérifié auprès de **`sum.golang.org`**, un journal public
inaltérable. Une dépendance republiée avec un contenu différent est détectée.

La variable `GOPRIVATE` exclut les modules privés de ces services.

## Autres nouveautés

- **TLS 1.3** est activé par défaut.
- `sync.Pool` résiste mieux aux cycles du GC, ce qui réduit les pics de
  latence.
- L'allocation et la libération de mémoire sont plus efficaces, et le runtime
  rend la mémoire au système plus vite.

## À retenir

`%w`, `errors.Is` et `errors.As` sont aujourd'hui la base de la gestion des
erreurs en Go. Voir le chapitre [Gestion des erreurs](../../langage/erreurs/).
